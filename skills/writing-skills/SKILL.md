# Writing Skills

Follow the [shared policy](../using-superpowers/references/workflow-policy.md), reading it once if needed.

Supply useful workflow knowledge without constraining unrelated tasks. Keep descriptions narrow, essential decision rules in SKILL.md, and substantial conditional detail in linked references. Avoid speculative rules and repeated host instructions.

Before behavioral changes, identify the observed problem and measurable outcome. Preserve a baseline and compare candidate guidance with existing skills and, when useful, no additional guidance. If the control succeeds, record that result; do not invent failures or add rules solely to enforce ceremony.

For substantial changes, use realistic isolated tasks. An independent subagent pass is appropriate when delegation is available and meaningful validation warrants it. Give the evaluator the task, skill, and raw artifacts without an expected answer. Read [testing-skills-with-subagents.md](testing-skills-with-subagents.md) for evaluation design.

Specify outcomes and decision criteria for open-ended work. Reserve fixed procedures for fragile operations with demonstrated invariants. Define actual authorization boundaries instead of requiring approval for every exception.

Validate frontmatter, names, references, metadata, and executable helpers. Structural checks do not establish behavioral success. Evaluate correctness, scope compliance, unnecessary pauses, repeated checks, and total effort; report sample size, model, host, and limits.

When working in this fork's source checkout, follow its repository evaluation instructions. Installed copies use task-specific fixtures without requiring the source-only test suite. Upstream policies apply only when submitting upstream. Creating a skill does not authorize installation, commits, pushes, or publication.
