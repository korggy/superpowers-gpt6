# Executing Plans

Follow the [shared policy](../using-superpowers/references/workflow-policy.md), reading it once if needed.

Read the plan and referenced requirements. Confirm the authorized workspace and recorded progress. User corrections update the plan; the plan does not override the current request.

Execute coherent tasks in dependency order and track evidence. Use subagent-driven-development only when delegation is available, permitted, and useful. Tool availability alone is not a reason to delegate.

Resolve routine plan defects from repository evidence and record consequential decisions. Investigate failed checks before concluding user input is needed. Ask about missing information or authority that blocks work, continuing independent work where possible.

A task is complete when its acceptance criteria and relevant checks are satisfied. Distinguish blocked, incomplete, and completed-with-disclosed-limitations work. Preserve recovery records for long plans.

Inspect aggregate changes for integration problems and report the result. Use finishing-a-development-branch when integration or cleanup is requested; an implementation-only request does not need a merge menu.
