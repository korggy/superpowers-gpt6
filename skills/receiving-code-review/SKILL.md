# Receiving Code Review

Follow the [shared policy](../using-superpowers/references/workflow-policy.md), reading it once if needed.

Read the complete feedback and inspect relevant code. Distinguish defects from preferences and misunderstandings. Verify external suggestions rather than accepting them automatically.

Implement clear authorized corrections. Ask about materially ambiguous items while continuing independent fixes. A real dependency can require waiting; one unclear unrelated item does not freeze the task.

Push back with evidence when suggestions violate requirements, break compatibility, introduce unused behavior, or conflict with user decisions. Reviewers do not grant publication authority or expand scope.

Prioritize correctness and acceptance. Batch related fixes with shared verification instead of running tests once per comment. Reuse valid results and rerun checks invalidated by changes.

Respond factually with changes, reasons for rejection or deferral, and evidence. Avoid prescribed praise or mandatory phrases. Reply to external review threads only when communication is authorized, using the project's forge tools.
